## Context

Longgu 当前仓库已有长篇小说创作相关示例和 OpenSpec 历史，但本次需求聚焦新的产品化工作流：中文网文长篇连载主编系统。目标用户不是工程师，而是希望用文件管理小说资产、又不想被英文目录和黑盒状态困住的中文作者。

设计约束：小说资产必须对作者可见、可读、可直接手改；流程必须能说明当前步骤、输入、输出、影响范围和下一步；长篇写作不能依赖每章都读取全部历史正文；首版以本地文件和 Markdown 模板为主，不引入 Web UI 或外部服务依赖。

## Goals / Non-Goals

**Goals:**

- 提供每本小说独立的中文目录项目模板。
- 用 `当前步骤.md` 作为默认入口，用 `创作流程.md` 作为全流程地图。
- 明确作者手改内容优先级最高，AI 推进必须尊重当前文件状态。
- 支持从立项、设定、大纲、伏笔、前情、章节规划、正文、AI 审稿到状态更新的闭环。
- 通过前情压缩、章节摘要和状态账本控制上下文读取量，减少重复情节和连续性错误。
- 让每章正文生成或作者写作前都有清晰的章节规划，写后有 AI 审稿和状态更新。

**Non-Goals:**

- 不做 Web UI、桌面端、多用户协作、账号、支付或云同步。
- 不做多模型 provider 管理或复杂 RAG。
- 不承诺一键自动生成整本小说。
- 不隐藏主要小说资产到 `.longgu/` 之类内部目录。
- 不把 AI 审稿结果当强制修改；最终决定仍由作者做。

## Decisions

### Decision 1: 使用中文可见目录承载小说资产

采用每本小说一个独立文件夹，目录形如 `01_立项设定/`、`02_设定圣经/`、`03_大纲/`、`04_伏笔与期待/`、`05_前情与状态/`、`06_章节规划/`、`07_正文/`、`08_AI审稿/`。

理由：中文作者能直接理解目录含义，也能直接打开和修改底层材料。编号提供顺序感，中文名称提供语义。

替代方案：使用英文工程目录或隐藏 `.longgu/`。放弃原因：英文目录增加理解成本；隐藏目录让作者感觉黑盒，且不利于每本小说天然隔离。

### Decision 2: 根目录三文件驱动流程

根目录保留 `当前步骤.md`、`创作流程.md`、`已确认决定.md`。

- `当前步骤.md` 是作者默认入口，描述当前阶段、应看文件、可改文件、影响范围、下一步产物和可回复指令。
- `创作流程.md` 是全流程地图，定义阶段顺序、读取规则、写入规则、确认关卡和跳转规则。
- `已确认决定.md` 是作者拍板记录，后续生成不得随意推翻。

理由：目录解决材料组织，流程文件解决“下一步怎么走”。两者分离，避免用户只看到目录但不知道路线。

### Decision 3: 作者手改文件是最高优先级输入

AI 每次推进必须读取当前步骤指定文件，并把现有文件内容当作真实状态。若作者修改上游文件，AI 必须提示可能影响哪些下游文件，而不是静默覆盖。

理由：小说创作需要作者主控。AI 是主编助手，不是唯一编辑入口。

### Decision 4: 章节规划取代“章节合同”命名

使用 `06_章节规划/第NNN章_规划.md`，不使用“章节合同”作为用户可见名。

理由：“章节合同”含义不直观；“章节规划”更符合中文作者理解。其内容仍保留任务书属性：本章作用、必须发生、不能发生、读者看点、爽点、伏笔、章尾钩子、连续性风险。

### Decision 5: 写新章使用上下文读取包，不读全部历史正文

写第 N 章时默认读取：当前步骤、创作流程、设定圣经、大纲、伏笔与期待、近期前情、角色状态、未解决问题、第 N 章规划、第 N-1 章正文。只有回收伏笔、角色回归、设定争议或作者指定时，才读取更早正文。

理由：长篇章节数量增长后，全量读取不可持续；摘要和状态账本能把读取量稳定在可控范围。

### Decision 6: 正文完成后必须进入 AI 审稿和状态更新

章节正文完成后，AI 审稿先对照规划、设定、大纲、伏笔、读者期待和前情状态检查正文；随后更新章节摘要、近期前情、角色状态、世界状态、关系状态、未解决问题、连续性风险和伏笔账本。

理由：长篇连续性不靠一次生成，而靠每章结束后的状态回灌。

## Risks / Trade-offs

- 中文文件名可能影响部分跨平台脚本或第三方工具兼容性 → 实现时必须使用 Unicode 安全路径处理，并在测试中覆盖中文路径。
- Markdown 表格适合作者阅读，但机器解析不如 JSON/YAML 稳定 → 首版优先可读性，必要结构可使用固定标题和表格约定。
- 作者手改上游文件会让下游产物过期 → 当前步骤或推进命令必须提示影响范围，并提供重建下游产物的选择。
- 每章都进行审稿和状态更新会增加步骤数 → `当前步骤.md` 必须清楚说明为何需要该步骤，并允许作者跳过非关键建议但不跳过状态更新。
- 不做隐藏内部目录会让项目文件数量较多 → 通过编号目录、`_说明.md` 和当前步骤导航降低迷路感，而不是减少必要资产。
